// case study

SOC-001: investigating repeated failed logons

A real investigation from my Splunk lab: five Event ID 4625 failures detected, triaged field by field, validated and closed as controlled test activity.

1,767Events Ingested
54625 Failures
694624 Events Seen
404PowerShell 4104 Events

Lab architecture

  • Ubuntu VM running Splunk Enterprise 10.4.3 as the lab server.
  • Windows 10 VM running Splunk Universal Forwarder 10.4.3; both hosted in VMware Workstation.
  • Forwarding over TCP 9997 into a dedicated index: Security, System, Application and PowerShell Operational logs.

Detection search (lab-adapted SPL)

index=soc-project1 LogName=Security EventCode=4625
| eval target_user=mvindex(Account_Name,1)
| stats count by Source_Network_Address, target_user
| where count >= 5
| sort -count

Result

Five failures for a local test account from loopback — a candidate investigated as controlled activity, not a confirmed incident.

Investigation record

  • Date: 20 Sep 2026
  • Context: local test account and loopback source on the lab endpoint
  • Findings: five Security 4625 events, interactive logon type, bad-password status
  • Compromise: not observed · Decision: controlled test activity, case closed

Lessons learned

  • Filter on the Security log — Application-log records can also use event ID 4625.
  • Use the actual extracted fields for account, source address and logon type.
  • Use a stable, documented server address; the forwarder stopped after the lab server address changed.
  • Next detection work: add 4740 monitoring and test 4624-after-4625 correlation.

Implementation status — what is built and what is next

✅ Implemented

  • Splunk Enterprise, index and TCP 9997 receiving
  • Universal Forwarder and Windows log ingestion
  • 4625 investigation and threshold detection logic
  • SOC-001 incident case
  • LimaCharlie sensor enrolment and benign scheduled-task test

🛠️ Designed / in progress

  • 4624 correlation after repeated failures
  • Six-panel SOC dashboard and five-minute alert
  • PowerShell 4104 hunting (404 events present)
  • LimaCharlie rule validation: alert, process tree, response

🔭 Planned

  • Sysmon telemetry
  • Linux SSH (auth.log) monitoring
  • Multi-endpoint correlation
  • API-driven reporting

Evidence boundary: SOC-001 is a closed benign lab case, not a real-world compromise. The source report does not include the saved-alert configuration screenshot or evidence of an alert firing, and it does not establish that the full six-panel dashboard was completed.
